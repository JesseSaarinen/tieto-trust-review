# Decision log

Short entries: what we decided, why, what we gave up. Newest last. An entry changed later says so and points to the entry that changed it.

| # | Date | Decision | Why | Trade-off |
|---|---|---|---|---|
| D1 | 13 Nov | The AI review is advice with evidence, never the approval. A named owner signs every merge. | Tieto's stance; accountability can't sit with a model. | The human step never disappears, it only shrinks. |
| D2 | 13 Nov | Story-first: the pack opens with the change's own explanation, split into claims. | A human can check a story in minutes; a 1,000-line diff takes an hour. | The story can be wrong, so it never counts as evidence by itself (D4). |
| D3 | 13 Nov | Breaker from a different vendor (Gemini) whose only job is to disprove claims. | Two vendors so the AI isn't grading its own homework; an adversarial prompt finds more than a "review this" prompt. | Two API bills; the breaker can over-dispute, which pushes work back to humans (measured as reading load and false alarms). |
| D4 | 13 Nov | Only "test run" and "static check" count as evidence. "AI reading only" is shown, but never makes a claim "backed". | Model statements can be confidently wrong; tests and deterministic checks can't be talked into passing. | Changes with weak tests route to humans more often. That is the intended pressure. |
| D5 | 13 Nov | The tool verifies the models' citations itself: cited files must be in the change, cited lines must exist, named tests must exist in the actual test run. | Cheapest hallucination guard; a claim that cites lines that don't exist is disputed automatically. | Doesn't catch a real line cited for the wrong reason (the breaker's job). Tightened in D19: a named test missing from the run is no evidence. |
| D6 | 13 Nov | Refuse-to-decide is triggered by deterministic checks first (S3–S8); AI-suggested refusals are shown and put their lines on the reading list, but never force a full read on their own. | Contracts and safety must not depend on a model noticing them. A model that over-refuses would send everything to full read and kill the time saving. | A contract the static rules miss is only caught if the AI suggests it. |
| D7 | 13 Nov | Routing by risk, not size: light check / focused read / full read. | #2297 touches 237 files but 222 are generated snapshots with one repeated edit; #2129's 28 files include a new public attribute. Size gets both wrong. | Rules are hand-written per repo (shipped assemblies, wire-format patterns). That's configuration a team owns. The level is now a label on the reading list (D19). |
| D8 | 13 Nov | Generated snapshots are not shown to the models; a static check (S2) proves they all change the same way, and the snapshot tests compare them to the real generator output. | 222 files of identical edits would drown the models and the human. | A hand-edited snapshot that happens to match the common shape would pass S2; the snapshot tests are the backstop. |
| D9 | 13 Nov | Tests run in a throwaway git worktree, never in the shared checkout. | Another session plants bugs in the same repo; switching branches under it would corrupt both. | Disk space and a fresh build per commit. |
| D10 | 13 Nov | A test project that fails to build is rebuilt on the base commit. If the base fails too, it's "pre-existing", not blamed on the change. | `MessagePack.SourceGenerator.ExecutionTests` doesn't build on this machine even on the base commit. Blaming the change would be a false alarm. | One extra build per failing project. |
| D11 | 13 Nov | Tests blocked by the machine (Windows Application Control) count as "not run", never as failures. | On #2129, 169 tests "failed" because Windows blocked a freshly built DLL. Reporting that as a code defect would be exactly the unexplained noise Tieto warns about. | The pack shows fewer test-backed claims on that branch, and those claims release no lines (D18). |
| D12 | 13 Nov | Accepting a change requires acknowledging every refusal by id and writing the residual risk. The tool refuses to save an "accept" without both. | The signature must say what wasn't checked and what risk the owner takes. | One more step for the owner; deliberately not skippable. |
| D13 | 13 Nov | Trust ledger per code area (first three path segments). An escape puts the area on probation (full read) until 5 clean sign-offs. | Trust earned per area and withdrawn after escapes is Tieto's stated model. | Area granularity is coarse; a team would tune it. |
| D14 | 13 Nov | Stack: TypeScript on Node 24, run without a build step; official Anthropic and Google SDKs. | Jesse's stack; zero build friction during a hackathon. | Not a product; a reference implementation. |
| D15 | 13 Nov | Model: Claude Opus 5.5 (author, effort high, structured JSON output). Gemini 4 Carbon (breaker, JSON schema output), falling back to Gemini 4 Argon and 3.8 Flash. | Strongest available models for code reading (Carbon is Google's strongest as of Nov 2026, checked against the key's model list); structured outputs make the pack machine-checkable. | About 6 minutes per review, most of it the breaker thinking (measured in D24). |
| D16 | 14 Nov | Measurement runs (planted bugs, repeated runs) never read or write the trust ledger; only real reviews and owner sign-offs do. | The ledger is a track record of real decisions. Batch runs had inflated "reviews" to 42 on some areas; the ledger was reset on 14 Nov. | The ledger starts empty for the demo. |
| D17 | 14 Nov | **Changed 14 Nov, was "each planted-bug branch runs 3 times, totals only".** Each of the 32 branches runs once; 6 seeded branches run 3 times for variance, picked by branch number and not by any result (the two lowest-numbered of the two largest requirement families, the lowest of the other two: seeded-01 to -06). A separate session scores against the hidden key, and the key is published in the repo after the final score. | One run per branch is what the budget buys; three runs on a fixed subset still shows model variance. Publishing the key lets judges check every number. | Variance is known for 6 branches, not 28. Until the key is published, misses can't be inspected by anyone outside the scoring session. |
| D18 | 14 Nov | **Fails closed.** If any part of the reviewer is missing or fails, the change routes up, never down, and the pack names the missing part in a banner above the routing line. No author, a failed author call or 0 claims: full read of every non-generated file. No breaker, a failed breaker call, or a claim the breaker gave no verdict on: that claim releases nothing. Tests off, blocked or broken: no line is released. A crash anywhere still writes a pack, and that pack is a full read. Runs with `--no-tests` or `--no-breaker` say so at the top. | On 13 Nov the stubbed #2283 pack routed to light check with 0 claims, and 21 of the 32 no-model packs did the same (18 of the 28 seeded branches). An absent reviewer looked like a clean review. | A flaky model API or a locked-down laptop turns into reading for the owner. That is the right direction for the cost to fall. |
| D19 | 14 Nov | **Routing is a reading list, line by line.** Every changed line starts on the owner's list. A code line comes off only when a claim that cites it is backed by tests the tool found passing in the real run **and** the breaker upheld that claim. Generated snapshots come off only through static check S2. A dispute, a refusal or a finding puts lines back. Lines no claim cites stay on the list. A static check can back a claim but does not release the lines it cites. | The old routing only read what was flagged, so a line no claim mentioned was read by nobody: the author could lower the reading by saying less. Now the AI can add reading and never remove it; only evidence the tool verified removes it. | Reading load is higher than "read the flagged parts", and it depends on how well the tests cover the change. A passing test backs a claim only as far as the test goes. |
| D20 | 14 Nov | **Two-sided metric.** Per pack: reading load = changed code lines the owner must read / changed code lines (generated and docs excluded). Per planted bug: in view = its lines are on the reading list or a finding names them; escape = not in view, at any routing level. Reported per layer, with false alarms on the 4 clean branches. | The planned headline, "a planted bug that ended on light check", was 0 by construction: no real pack reached light check (19 of 19 were focused or full read). A number that cannot move measures nothing. Load and escapes are the two things that trade against each other: review time and incidents. | Two numbers to explain instead of one. |
| D21 | 14 Nov | Raw model outputs are saved in every pack, and `regrade` rebuilds a pack offline with layers removed: L0 deterministic checks and tests, L1 + Claude with the breaker removed, L2 both models. No model is called. | Three layers from one paid run instead of three paid runs, and the breaker's effect is isolated on the same author output. | L1 is a counterfactual (lines released on passing tests alone); a live run without the breaker releases nothing. L1 packs carry a "measurement pack" banner. |
| D22 | 14 Nov | Each claim's requirement quote is checked against the requirement text (word by word, ignoring formatting); a quote that is not there disputes the claim. The pack also lists requirement sentences no claim quotes. | "Evidence traced to the requirement" needs the trace checked in both directions, and an invented quote is the same hallucination as an invented line number. | An issue body is mostly context, so the "not quoted" list is something to skim, not a score. |
| D23 | 14 Nov | The reviewer is on the ledger too. The planted-bug run is a standing audit, not a one-off: seeded bugs per code area on a schedule, each escape recorded on that area's ledger entry. | Answers "what would make you not trust your own output" with a mechanism instead of a promise. | Someone has to keep planting bugs, and keep the key away from the reviewer. |
| D24 | 14 Nov | Every pack records tokens, list-price cost and seconds for both models. | The first 19 packs were run without measuring spend. "It scales" needs a price per review. | List price, not the invoice: the Gemini key is an event lab account. |
| D25 | 14 Nov | Prompt v3 for the measurement: claims are narrow (one behaviour or one test method each), every claim cites the full ranges it accounts for, and the breaker disputes over-citation. The 19 packs from 13 Nov (prompt v1) are kept as history and left out of the measurement. | Under D19 a broad claim is all-or-nothing: on the first v2 run one dispute on a claim covering the whole test file put 173 lines back. Packs from different prompts are never mixed in one table. | All 32 branches had to be run again. |
| D26 | 14 Nov | The scoring rules are fixed before any result is opened, and the score stands as the rules give it. One bug (seeded-01) counts as an escape at every layer although a finding describes it, because that finding sits 9 lines outside the 3-line window. The denominator is what the key holds: 22 planted bugs and 6 clean controls among the 28 seeded branches, not 28 bugs. | A rule changed after seeing the result measures nothing. The reviewer side was blind to the key, so only the scoring session could know the denominator. | The headline is 21 of 22, not 22 of 22. D17, D18 and D20 were written when we believed all 28 seeded branches carried a bug. |
