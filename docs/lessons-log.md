# Lessons log

Failure modes we hit while building and running the reviewer, and what we changed. Newest last.

| # | What happened | Failure mode | What we changed |
|---|---|---|---|
| L1 | First version of the public-API regex hung the whole review on long lines. | A "deterministic" check can itself fail silently (catastrophic regex backtracking). | Replaced with a linear-time pattern. Checks must be cheap and boring. |
| L2 | On #2129, 169 of 173 tests "failed". All with the same message: Windows Application Control blocked a freshly built `MessagePack.dll`. | Environment failure reported as code failure: the pack would have told the owner the change is broken when it isn't. | Failures matching machine-policy errors are reclassified as "blocked by the machine" and count as not run (D11). |
| L3 | `MessagePack.SourceGenerator.ExecutionTests` failed to build on #2234 (`CS0117 ... 'Instance'`). | Pre-existing breakage blamed on the change. Checking the base commit showed the same error. | Failing test builds are retried on the base commit; if that fails too it's labelled pre-existing (D10). |
| L4 | The .NET SDK wasn't installed when the tool was first run, then appeared mid-session. | Evidence availability changes between runs; packs must say exactly what was and wasn't run. | Every pack has a "What was NOT checked" section built from the actual run, not from a template. |
| L5 | The Windows Code Integrity log confirmed Smart App Control blocks every freshly built, unsigned test DLL, intermittently (#2283 and #2297 ran, #2129 and #2234 were blocked). The same block likely stops the source generator during the `ExecutionTests` build, which explains the "pre-existing" CS0117 errors. | The evidence layer depends on the machine. A reviewer on a locked-down laptop silently has less evidence than one in CI. | Runner retries once, labels blocked projects, and compares compile errors with the base so only errors the change adds are reported. Real fix: run tests in CI or a container, never on a developer laptop. |
| L6 | On seeded-27 the planted-bug scorer saw test status "error", every project "no results". The real cause was a NuGet restore failure (`NU1605`/`NU1109` package downgrade); the runner only recognised `CS`/`MSB` error codes. | A broken build reported as "no evidence" instead of "this change breaks the build". The second session's outside view caught it, not our own checks. | Restore errors (`NU`) now count as build errors and are compared with the base like compile errors. seeded-27 now reads "build failed, introduced by this change". |
| L7 | The first #2283 pack was made without API keys. It had 0 claims and routed to **light check**. So did 21 of the 32 packs made with no models at all, 18 of them seeded branches. | Fail open: an absent reviewer looked exactly like a clean review. Nothing disputed, nothing refused, so nothing to read. | Fails closed (D18): a missing or failed part can only add reading, and the pack names it in a banner above the routing line. `npm run selftest` removes each part in turn and checks the change routes up; it spends nothing. |
| L8 | In 2 of the first 19 model runs the breaker answered with an almost empty list: 0 verdicts for 7 claims on one branch, 1 for 8 on another. The tool recorded both as normal runs and the packs showed "no disputed claims". | A silent breaker counted as a breaker that found nothing. Found only when the old packs were regraded under the new rules. | The breaker is asked once more for the claims it skipped. A claim still without a verdict counts as unchallenged and releases no lines, and the banner names it (D18). |
| L9 | No real pack reached light check: 19 of 19 were focused or full read, the clean branches included. The planned headline metric was "planted bugs that ended on light check". | A metric that cannot move. It would have been 0 escapes whatever the reviewer did, and we would have reported it as a result. | Two-sided metric (D20): reading load per pack, and per planted bug whether it was in view. One cannot be gamed without the other moving. |
| L10 | Reviewing our own routing: the owner was only sent to flagged lines, so a changed line that no claim mentioned was read by nobody. | The author model could lower the reading by saying less. "The AI's confidence never moves a change" was true of the confidence field and false of the silence. | Routing is a reading list (D19): every changed line starts on it and only verified evidence takes a line off. The self-test checks that stated confidence changes nothing and that adding the breaker never lowers the load. |
| L11 | The measurement batch died at about 00:17 when the laptop went to sleep: 7 reviews "FAILED (no output)", runs 2 and 3 never started. Nobody knew what had been spent either: the tool dropped Claude's token usage and never read Gemini's. | A long unattended run with no restart and no meter. | `batch` skips finished packs, so it can be started again; the session keeps the machine awake while it runs. Every pack records tokens, list-price cost and seconds (D24). |
| L12 | First run under the reading-list rule: the author wrote one claim covering the whole test file (173 lines). The breaker disputed it for over-citation, correctly, and all 173 lines went back: reading load 95%. | All-or-nothing claims. One dispute on a broad claim erases everything the tests had earned. | Prompt v3 (D25): one behaviour or one test method per claim. Same branch, next run: 12 claims, 2 disputed, reading load 32%. |
| L13 | The first requirement-quote check disputed a real quote: the author had joined the heading "Expected behavior" and the sentence under it with a colon. | A checker's own false alarm: a formatting difference reported as an invented quote. | Quotes are compared word by word, ignoring punctuation and markdown. An invented quote still fails (covered by the self-test). In the 32-branch run the check found no invented quote and no invented line in 525 claims. |
| L14 | On 10 of 32 reviews Gemini reported 3 to 6 times more input tokens than the prompt holds, for one call and one attempt (50,712 for a prompt of about 8,500). Reviews of same-size changes cost from $0.39 to $0.84. | A price per review worked out from prompt size is wrong by up to a factor of two. The provider's meter is the only source. | Each pack keeps the provider's own usage record per call, and the cost is computed from that. The concept card quotes the measured mean and range, not an estimate. |
| L15 | On seeded-15 the breaker's answer hit Gemini's 65,536-token output limit and came back as cut-off JSON, in the middle of the batch. | A model failure nobody was watching for. | Nothing had to change: the pack failed closed on its own. Full read, with "breaker: Gemini call failed" in the banner. The measurement counts it as one of the 32 runs instead of rerunning it until it looked good. |
| L16 | Three runs of the same branch gave reading loads of 67%, 36% and 27%. Across 6 branches the spread between runs was 6 to 40 points, 26 on average. | A single run's number looks like a property of the change and is partly a property of that run: the author writes different claims and the breaker disputes different ones. | Nothing in the tool. The concept card reports the spread next to the means, and lists it as a limit. The floor is not affected: no run can release a line without a passing test and an uphold. |
| L17 | The scoring session opened the answer key and found 22 planted bugs and 6 clean controls. Every document on the reviewer side said "28 planted bugs". | A number nobody on our side could check was repeated across the concept card, the video script and the README. Blind by design also means blind to the denominator. | Denominators come only from the scoring step (`docs/measurement.md`, D26). The 6 controls turned out useful: none drew a finding about its harmless commit. |
| L18 | The one escape (seeded-01) is a planted change that takes back part of what the base change added. It leaves no changed line in the pull request, so it escaped at every layer, including L0, where the owner reads every changed line. | "Every changed line is on the list" says nothing about a line that should be in the change and isn't. A reading list built from the diff cannot hold an omission. | Nothing in the tool: the reviewer is not tuned to a planted-bug result. Both models did raise it (Claude as an open question, the breaker as a finding on an unchanged line), and the pack lists the requirement sentences no claim quotes. It is now a stated limit in the concept card, and the area is on probation in the ledger. |
