## 3. The story
Every generator template (object formatter, string-key formatter, enum, union, resolver, composite resolver) now puts `[global::System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverage]` on the type it emits. Each attribute sits inside an `#if !NETSTANDARD2_0 && !NETFRAMEWORK` block. The resolver templates also decorate their nested helper classes (`FormatterCache<T>` and `GetFormatterHelper`). One shared helper, `TransformUtilities`, now writes a line break after `{` for nesting types that have constraints. Without it, `#if` could land mid-line after the brace. The change adds a README note, a new test class with two tests, and 222 regenerated snapshot files.

**Why:** Issue 2297 asks for all generated MessagePack code to carry `ExcludeFromCodeCoverage`, so generated formatters stop skewing coverage numbers.

**Touches beyond the requirement:**
- TransformUtilities.EmitNestingTypesAndNamespaces now writes `{\r\n` instead of `{` when the nesting type has constraints. This changes whitespace in generated output for those types and is the likely cause of the odd +5/-1 and +4/-0 snapshot shapes.
- The README paragraph says the attribute is unavailable on netstandard2.0 and .NET Framework. That statement looks factually wrong.
- The attribute is applied to the user's own `partial` resolver class, not only to fully generated types.
- 222 expected snapshot files were regenerated to match the new output (S2 reports 7 distinct change shapes).

**How sure (the author's own view; it moves nothing):** High that the five templates exercised by the new test emit the attribute inside the guard, and that each .tt matches its .cs (S1). Medium on the composite resolver and the nested helper classes, which only snapshot tests cover and whose names are not in the diff. Medium on the TransformUtilities fix: it looks needed, but no named test targets it. Low confidence that the `#if` guard is justified: as far as I know, ExcludeFromCodeCoverageAttribute exists in netstandard2.0 and .NET Framework 4.0+, so the guard silently drops the feature for those targets.
