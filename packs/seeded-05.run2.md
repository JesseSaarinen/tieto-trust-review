## 3. The story
The source generator templates now put `[global::System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverage]` on each generated type. That covers the object formatter (int-keyed and string-keyed), enum, union, the generated resolver and its nested `FormatterCache<T>` / `GetFormatterHelper` classes, and the composite resolver and its `FormatterCache<T>`. Every attribute is wrapped in `#if !NETSTANDARD2_0 && !NETFRAMEWORK`. A one-line fix in TransformUtilities emits a line break after `{` when nesting types have constraints, so the `#if` lands at the start of a line. The 222 snapshot files were regenerated, and a README note and a new two-test file were added.

**Why:** The issue asks that all generated code carry ExcludeFromCodeCoverage so it does not skew coverage numbers.

**Touches beyond the requirement:**
- TransformUtilities.cs line 58 changes the generated whitespace for every nested type with generic constraints. It is needed so the `#if` directive starts a line, but it alters output that was not otherwise touched.
- README.md gains a doc note. Its claim that the attribute is unavailable on netstandard2.0 and .NET Framework appears to be wrong.
- The `#if !NETSTANDARD2_0 && !NETFRAMEWORK` guard is the agent's own design decision. It is not in the requirement, and it narrows who gets the feature.

**How sure (the author's own view; it moves nothing):** High that the six templates and their compiled .cs files emit the guarded attribute at the places shown. Low on the guard premise: ExcludeFromCodeCoverageAttribute ships in .NET Framework 4.0+ and in netstandard2.0, so consumers on those targets get no exclusion. Medium on the new tests: they check per file, not per type, and they never compile the generated code. The 222 snapshots were only sampled (2 shown), and the uniformity check S2 fails with 7 shapes.
